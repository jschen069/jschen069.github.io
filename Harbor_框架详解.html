总览一、定位与核心概念

Harbor 是一个 Agent 评测编排框架：把「任意 Agent × 任意任务集 × 多次尝试」组织成可并发、可重试、可断点续跑的评测作业（Job），在容器化沙箱里执行「Agent 干活 → 脚本判分」两阶段，最后聚合出指标。它本身不实现任何 Agent 和判分逻辑——这两者分别通过 Agent 插件体系（48+ 内置）和任务自带的 tests/test.sh 承载。

概念定义代码位置
Task一个评测单元的目录：task.toml（超时/资源/元数据）+ instruction.md（任务指令）+ environment/（Dockerfile/compose）+ tests/test.sh（判分脚本）+ solution/（可选参考解）models/task/
DatasetTask 的集合（一个 benchmark 对应一个 dataset 目录）models/job/config.py
Agent完成任务的一方，实现 BaseAgent.setup/run；installed 型 Agent（openhands、claude-code 等）在任务容器内安装运行agents/
Environment容器化沙箱，实现 BaseEnvironment；默认 docker（docker compose 驱动），另有 daytona/e2b/modal 等 29 种environments/
Trial一次「某 Agent 尝试某 Task」的完整执行（环境启停 + Agent 运行 + 验证），产出 rewardtrial/trial.py
JobTrial 的集合：n_attempts × tasks × agents 笛卡尔展开，负责并发调度与结果聚合job.py
Verifier验证器：在容器内执行 tests/test.sh，解析 /logs/verifier/reward.txt|jsonverifier/verifier.py
Adapter离线数据转换器：把外部 benchmark（如 SWE-bench）转成 Harbor Task 格式，运行时不参与adapters/
Metric指标计算器（Mean/Max/自定义脚本），对每个「agent__model__dataset」分组聚合 rewardsmetrics/

├─────────────────────────────────────────────────────────────────┤

与 NL2RepoBench 的同构性：Harbor 的 Trial ≈ NL2RepoBench 的单个任务线程（start_app）；Verifier ≈ post_process_task；Job ≈ start_openhands 的分发循环。差异在于 Harbor 用 asyncio 单进程事件循环（NL2RepoBench 用线程池）、每阶段有超时与重试、结果有统一 schema。

入口三、入口层：CLI 命令与 JobConfig

3.1 命令注册（cli/main.py）

harbor / hr / hb            # 三个等价入口（pyproject entry_points → cli/main.py:app，Typer）
harbor run ...              # = harbor job start 的别名（main.py:167）→ jobs.py: start()
harbor trial start -p <task> -a <agent> -m <model>   # 单任务调试入口
harbor view / init / publish / hub / upload / dataset ...

3.2 配置构建（jobs.py: build_job_config，411 行起的巨型签名）

把 CLI 参数 + YAML/JSON 配置文件合并成 JobConfig（Pydantic 模型，models/job/config.py:396-449）：

参数族CLI 选项说明
配置来源-c/--config（可叠加）、-p/--path（本地任务/数据集）、-d/--dataset（registry）、-t/--task后者覆盖前者；-p 走本地路径完全不联网
Agent-a/--agent、-m/--model、--ak/--agent-kwarg、--ae/--agent-env支持 module:ClassName 自定义 Agent 零源码接入
沙箱-e/--environment（docker/daytona/e2b/...）默认 docker
并发/尝试-n/--n-concurrent、-k/--n-attempts并发与重复次数
执行模式--dry-run、--print-config、--launch、--uploadlaunch=云端托管（内网场景不用）

3.3 执行分发（jobs.py: _execute_job，1997 行）

1print-config / dry-run：校验并打印合并后的配置，不执行
▼
2launch 分支：--launch 走 hosted 提交（Harbor Hub 云端）；默认不走——本地执行
▼
3本地执行：await Job.create(config) → await job.run()，在当前进程内跑完全部 trial
前置检查 _run_preflight（jobs.py:113-128）：环境凭据 + Agent 选项校验。本地 docker 无凭据要求；云环境检查 API key。

编排四、Job 层：展开、断点续跑与目录契约

4.1 Job.create（job.py:136-184）——配置到可运行作业

① _resolve_agent_skills        # 解析 skills 来源（git/本地路径）
② AgentFactory.run_preflight   # 每个 Agent 的选项/凭据预检
③ _resolve_task_configs        # JobPlan：解析 -p/-d/-t 成 TaskConfig 列表
④ validate_resource_policies   # 环境资源策略校验
⑤ _resolve_metrics             # 每个数据集的指标集（缺省 Mean）
⑥ _cache_tasks                 # 任务下载/缓存到本地
→ Job 实例（构造函数内完成 trial 展开与续跑对账）

4.2 Trial 笛卡尔展开（job.py:405-429）

self._trial_configs = [
    TrialConfig(task=..., agent=agent_config, environment=..., verifier=..., ...)
    for _ in range(n_attempts)          # 尝试次数（外层）
    for task_config in task_configs     # 所有任务（中层）
    for agent_config in agents          # 所有 Agent（内层——错开模型供应商，优化限流）
]

一个 Job 的 trial 总数 = n_attempts × 任务数 × Agent 数。每个 TrialConfig 携带独立的超时乘数（agent/verifier/build 分开可调）。

4.3 断点续跑（resume）机制

  • Job 目录已存在 → 读 result.json 恢复 job UUID；逐个校验已有 trial_*/result.json，无结果的目录直接删除（job.py:278-280）
  • _init_remaining_trial_configs（347-377）：把计划的 TrialConfig 与已完成的逐一对账，只重跑缺失的；配置不一致则拒绝续跑
  • 重试时（retry）_remove_completed_attempt_for_retry（697-708）：撤回旧结果、指标重算、retries 计数 +1

4.4 Job 目录契约

jobs/{job_name}/
├── config.json      # 本次 JobConfig 快照（续跑校验依据）
├── lock.json        # 输入锁定（harbor 版本/任务摘要/Agent 版本），保证可复现
├── result.json      # JobResult：进度 + 统计 + 指标 + 全部 TrialResult（增量写入）
├── job.log          # 调试级完整日志
└── trial_*/         # 每个 Trial 一个目录（见第八节）

沙箱五、沙箱编排：TrialQueue + Environment 生命周期

5.1 TrialQueue 并发控制（trial/queue.py）

机制实现说明
并发上限asyncio.Semaphore(n_concurrent)（:45）同时运行的 Trial 数 = n_concurrent_trials（JobConfig，默认 4）
重试RetryConfig：include/exclude 异常类型过滤 + 指数退避 min_wait × multiplier^attempt（封顶 max_wait）（:83-110）基础设施类异常自动重跑，Agent 超时等可配置排除
Hook 体系TrialEvent：START / ENVIRONMENT_START / AGENT_START / VERIFICATION_START / AGENT_END / END / CANCELJob 挂钩实现实时统计；进度 UI 挂钩实现状态展示
Agent 级限流每 Agent 独立信号量池（:46-48）同一模型供应商的并发可单独限制

Job 侧提交方式（job.py:1177-1182）：submit_batch(remaining_trial_configs) → asyncio.TaskGroup 并发收口。

5.2 DockerEnvironment 生命周期（environments/docker/docker.py）

1start(force_build)（:966）：写四份 compose 覆盖文件（挂载/资源/环境变量/egress 出网控制）→ 决定用预构建镜像（task.toml [environment].docker_image）还是现场 docker compose build（同名镜像并发构建用锁串行化 :1009-1016）
▼
2镜像 OS 校验（:1018-1025）→ 清理残留：compose down --remove-orphans（:1027-1031，同 session ID 的旧容器）
▼
3启动：compose up（启用 egress 控制时先拉起网络策略 sidecar 再起主服务 :1034-1044）→ 轮询 exec true 直到容器可执行命令（:1044,1076）
▼
4挂载目录准备：/logs/{agent,verifier,artifacts} 建目录并 chmod（:1046-1052）→ 上传 environment/ 目录（:1054）
▼
5运行期：exec()（:1311，以指定用户执行命令）、upload_dir / download_dir（:1197,1263）、可选 SSH 流式访问
▼
6stop(delete)（:1143）：验证完成后停止并（默认）删除容器

5.3 容器内路径契约（models/trial/paths.py）

/                        容器根
├── logs/                 ★ 与宿主 trial_dir/ 双向挂载
│   ├── agent/            #   宿主 trial_dir/agent/   ← Agent 日志/轨迹落这里
│   ├── verifier/         #   宿主 trial_dir/verifier/← 判分输出，reward.txt 在此
│   └── artifacts/        #   宿主 trial_dir/artifacts/
├── tests/                ★ Verifier 阶段才注入（任务目录的 tests/ 上传到此）
└── solution/             ★ 仅 OracleAgent 使用（跑参考解）
防作弊的关键：tests/ 不在镜像里、不在挂载卷里——它由 Verifier 在 Agent 阶段结束后 upload_dir 进容器。Agent 运行期间无法看到判分脚本与测试内容。

6.2 Agent 阶段执行（trial.py:540-624）

_emit(AGENT_START)
with 网络策略上下文(phase=agent):          # task.toml [agent].network_mode 生效于此
  with scoped_exec_env(agent.extra_env):    # LLM_API_KEY / LLM_BASE_URL 等注入
    with 日志上下文(/logs/agent):
      with sync_trajectory(...):            # 实时轨迹同步到宿主
        await asyncio.wait_for(             # ★ 超时硬控制
            agent.run(instruction, environment, context),
            timeout=timeout_sec)            # task.toml [agent].timeout_sec × 乘数
except asyncio.TimeoutError → AgentTimeoutError
finally: _emit(AGENT_END)
控制维度机制说明
超时asyncio.wait_for（:608-615）到时取消协程，抛 AgentTimeoutError——被 SingleStepTrial 捕获记为异常但继续验证（single_step.py:84-85），部分完成也能得分
网络每阶段网络策略（:583-587）agent 阶段与 verifier 阶段独立配置（public / 限制 / egress sidecar 拦截）
凭据scoped_exec_env模型连接（api key/base URL）只在 Agent 阶段暴露给容器
产物/logs/agent 挂载 + sync_trajectory日志与轨迹实时落宿主，超时/崩溃不丢

6.3 Agent 阶段收尾（SingleStepTrial._run :38-55）

_run_agent()            # 含超时捕获 + _sync_agent_output
→ _upload_agent_logs()  # 非挂载型环境回传日志
→ _collect_artifacts()  # 按任务 artifacts 配置收集容器内文件
→ [SEPARATE 模式: 先停 Agent 环境]     # verifier 用独立容器
→ _run_verifier()
→ [SHARED 模式: 验证后停环境]          # 默认：同一容器两阶段

验证七、沙箱验证：Verifier 与 reward 协议

7.1 Verifier.verify() 全流程（verifier/verifier.py:166-268）

1定位测试脚本（_resolve_tests :124-163）：按目标 OS 找 tests/test.sh（或 .bat/.ps1）；多步任务支持步骤级测试目录
▼
2注入 tests/（:175-187）：environment.upload_dir(task/tests → 容器 /tests)——Agent 阶段已结束，此刻才可见；skip_tests_upload 可跳过（镜像自带判分脚本时）
▼
3合成执行命令（:189-219）：合并 verifier.env + 覆盖 env（支持 ${VAR} 解析）→ chmod +x → 以 verifier 用户执行，stdout 重定向到 /logs/verifier/test-stdout.log
▼
4回收验证产物（:234-255）：下载 /logs/verifier/ 整目录到宿主 trial 目录
▼
5解析 reward（:257-266）：reward.json（多指标 dict，优先）或 reward.txt（单浮点数）→ 校验有限数值 → VerifierResult(rewards=...)

7.2 reward 协议与失败语义

项规则
取值数值型（int/float），建议 0~1；非有限值（NaN/Inf/1e309）与字符串一律拒绝（:104-121）
缺失/空文件RewardFileNotFoundError / RewardFileEmptyError——test.sh 忘写 reward 会直接判失败
超时verifier 阶段独立超时（[verifier].timeout_sec），超时抛 VerifierTimeoutError（single_step.py:110-113）
验证模式SHARED（默认）：与 Agent 同容器——适合"检查 Agent 留下的文件状态"；SEPARATE：独立验证容器——适合需要干净环境的判分
典型 test.sh 模式（swebench adapter 实例）：跑测试命令 → 解析结果 → echo 1 > /logs/verifier/reward.txt。连续分数直接写浮点值（如 NL2RepoBench 适配的 passed/total）。

汇总八、结果汇总：TrialResult → JobResult

8.1 Trial 目录与 TrialResult（trial 结束即落盘）

trial_{name}/
├── agent/            # Agent 日志 + trajectory.json（ATIF 格式）
├── verifier/         # reward.txt / reward.json / test-stdout.log
├── artifacts/        # 收集的容器内产物 + manifest.json
├── config.json       # 本 Trial 完整配置（复现依据）
├── lock.json         # 输入锁定
├── result.json       # ★ TrialResult（_finalize 时写入，trial.py:514）
└── trial.log

TrialResult 字段：trial_name / task_name / source / agent_info(Agent+模型)
  / agent_result(AgentContext: token、cost) / verifier_result(rewards)
  / agent_execution + verifier(TimingInfo) / exception_info(异常栈)

8.2 JobResult 聚合（job.py:953-1093）

1实时聚合：每完成一个 trial，_on_trial_completed hook（:917-951）更新 rewards 映射 → 增量写 result.json（排除明细以控体积）——看板/监控可随时读取中间态
▼
2最终聚合（:1033-1072）：合并新跑 + 续跑已有结果 → 按「agent__model__dataset」分组 → 每组算指标（Mean 等可自定义）+ pass@k（n_attempts > 1 时自动计算）
▼
3落盘：JobResult（进度统计 + evals 指标 + 全部 TrialResult）写 jobs/{job}/result.json；harbor view 起本地 Web 查看器浏览
聚合维度键格式内容
evals 分组agent__model__dataset每组：metrics 列表（各指标计算值）+ pass_at_k + reward 分布
进度统计JobStatsn_total / n_running / n_cancelled / n_retries，实时刷新
